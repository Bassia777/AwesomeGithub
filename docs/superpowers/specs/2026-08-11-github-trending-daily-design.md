# GitHub 热榜日报自动化工具设计

## 1. 目标

构建一个免费优先、无需自有服务器的自动化工具。工具每天北京时间 08:00 获取 GitHub Daily Trending 全球、全语言榜单前五名，为每个项目生成不超过 200 个中文字符的简明介绍，并以五张明亮卡片组成 HTML 日报，通过 Gmail 发送到用户配置的一个或多个收件邮箱。

项目说明需要覆盖三个要点：项目背景、解决的痛点、值得关注的原因。说明应使用通俗、直接的中文，避免堆砌术语。

同一项目若连续多日进入前五，日报标注“连续霸榜第 X 天”；中断一天后再次上榜时，连续天数重新从 1 计算。

## 2. 已确认的产品范围

- 数据源：GitHub Daily Trending，而非全 GitHub 精确 Star 增量排名。
- 榜单范围：全球、全部编程语言，不过滤教程、资源清单等仓库类型。
- 展示数量：每日前五名。
- 执行环境：GitHub Actions。
- 调度时间：UTC 00:00，即北京时间 08:00；接受 Actions 排队导致的少量延迟。
- 手动执行：支持从 GitHub Actions 页面手动触发，用于首次测试和补跑。
- 发件方式：Gmail SMTP。
- 收件地址：由用户通过 GitHub Secrets 配置，支持单个或多个 Gmail、QQ、公司邮箱等标准邮箱地址，不在代码中写死。
- 邮件样式：浅色背景、五张纵向独立卡片，优先保证 Gmail、QQ 邮箱及常见公司邮箱客户端的兼容性。
- 历史记录：每日 JSON 与 Markdown 保存到仓库，并由 Action 自动提交。
- 本期不包含：管理后台、外部数据库、多语言榜单筛选、多个邮件模板、订阅管理和自有服务器部署。

## 3. 技术方案选择

采用 Python 模块化脚本配合 GitHub Actions。

该方案依赖少，适合抓取网页、处理 JSON、调用 HTTP API、渲染邮件和通过 SMTP 发信。相比 TypeScript，它不需要额外构建步骤；相比拼装多个第三方 Action，它更容易控制 AI 降级、连续上榜计算和错误处理，也减少供应链依赖。

GitHub Trending 没有正式公开 API，因此需要解析网页。解析器必须使用固定样本进行测试，并在页面结构改变导致解析失败时发送异常日报。

## 4. 系统架构与数据流

正常流程如下：

1. GitHub Actions 通过定时或手动触发启动 Python 程序，并注入 GitHub Secrets。
2. Trending 模块抓取 GitHub Daily Trending 全球全语言榜单，解析前五个仓库。
3. Repository 模块通过 GitHub API 补充 Stars、主要语言、仓库简介和 README。
4. Streaks 模块读取昨日记录，计算首次上榜或连续霸榜天数。
5. Summarizer 模块生成不超过 200 个中文字符的项目说明。
6. Renderer 模块生成五张浅色项目卡片组成的 HTML 邮件及 Markdown 历史日报。
7. Mailer 模块通过 Gmail SMTP 发送邮件。
8. 邮件发送成功后，保存当日 JSON 和 Markdown，并由 Action 提交到仓库。

## 5. 模块边界

### 5.1 Trending

负责请求和解析 GitHub Daily Trending，只输出标准化的前五项目标识、排名及页面可得信息，不负责 GitHub API 补充、摘要或邮件发送。

### 5.2 Repository

通过 GitHub API 获取仓库 Stars、主要语言、简介、链接和 README。单个仓库的 README 获取失败时返回可用的基础信息，不阻断其他项目。

### 5.3 Streaks

读取上一自然日的成功日报 JSON。若同一 `owner/repository` 昨日出现且今日仍出现，连续天数加一；否则设为一。Trending 整体失败时不写入当日成功历史，因此不会错误中断或增加连续天数。

### 5.4 Summarizer

暴露统一的摘要接口，并按以下顺序自动降级：

1. Gemini API
2. GitHub Models
3. DeepSeek API
4. GitHub 仓库原始简介

AI 提示词要求输出简体中文、最多 200 个中文字符，并覆盖背景、痛点和优势。每次结果需要经过长度和空内容校验。某一级失败、超时或输出无效时自动尝试下一级，不中断日报。

### 5.5 Renderer

负责两种邮件：

- 正常日报：标题、日期、榜单范围及五张纵向浅色卡片。
- 异常日报：红色提示风格，说明失败阶段、重试情况和原因分析。

正常卡片包含排名、仓库名、Stars 总数、主要语言、首次上榜或连续霸榜天数、中文说明及项目链接。HTML 使用内联样式和明确的 UTF-8 声明，以提高邮件客户端兼容性并防止中文乱码。

### 5.6 Mailer

只负责通过 Gmail SMTP 发送给配置的收件人，不参与内容生成。使用 Gmail 应用专用密码，不使用 Gmail 登录密码。

收件人通过 `MAIL_TO` 配置，多个地址使用英文逗号分隔。发送前需要去除首尾空格、过滤重复地址并校验基本邮箱格式。配置为空或全部地址无效时，任务应在发送前明确失败并记录原因。正常日报和异常日报使用同一收件人列表。

### 5.7 Main

负责编排各模块，选择正常日报或异常日报路径，设置日志和进程退出状态。

## 6. 历史数据设计

每日成功运行生成一份以日期命名的 JSON，至少包含：

- 日期和生成时间
- 榜单范围
- 排名
- 仓库唯一标识 `owner/repository`
- 项目链接
- Stars 总数
- 主要语言
- 连续上榜天数
- 中文摘要
- 摘要来源：Gemini、GitHub Models、DeepSeek 或 repository description

同时生成同日期的 Markdown 日报，方便直接在仓库中阅读和回溯。

只有正常日报成功发送后才写入并提交成功历史，避免出现“历史显示成功但邮件未送出”的状态。Action 的自动提交仅允许修改日报历史目录。

## 7. 调度与密钥

GitHub Actions 同时配置：

- Cron：`0 0 * * *`
- 手动触发：`workflow_dispatch`

敏感配置全部存放在 GitHub Secrets：

- `GEMINI_API_KEY`
- `DEEPSEEK_API_KEY`
- `GMAIL_USERNAME`
- `GMAIL_APP_PASSWORD`
- `MAIL_TO`

`MAIL_TO` 接受单个地址，例如 `wangyaoyi@bigo.sg`，也接受英文逗号分隔的多个地址，例如 `wangyaoyi@bigo.sg,user@qq.com,user@gmail.com`。修改收件人不需要改动代码，只需更新 GitHub Secret。

GitHub Models 优先使用 Actions 提供的 GitHub Token，并给予所需的最小权限。密钥及完整收件人列表不得写入日志、JSON、Markdown、邮件正文或提交记录。

## 8. 异常与降级策略

### 8.1 Trending 整体失败

请求超时、HTTP 错误、解析异常或有效项目不足五个时，最多重试三次，并采用递增等待。三次后仍失败则生成并发送异常日报，不静默结束，也不修改成功历史。

异常日报包含：

- 执行时间
- 失败阶段
- 重试次数
- 精简后的原始错误
- 可能原因，例如网络异常、限流或 Trending 页面结构变化
- GitHub Actions 本次运行链接
- 建议检查项

若 Gmail 本身也发送失败，无法再通过邮件告警，此时错误保留在 GitHub Actions 日志中，并使工作流以失败状态结束。

### 8.2 单仓库数据失败

单个 README 或补充信息获取失败时继续处理，并使用仓库简介或已有字段。若最终无法形成五张有效卡片，则按 Trending 整体失败处理，发送异常日报。

### 8.3 AI 服务失败

按 Gemini、GitHub Models、DeepSeek、仓库原始简介的顺序降级。任何 AI 服务失败都不阻断日报。

## 9. 测试策略

### 9.1 单元测试

- 使用固定 HTML 样本测试 Trending 解析及前五结果。
- 测试首次上榜、连续多日上榜、中断后重新上榜。
- 测试摘要空值和 200 字限制。
- 测试 AI 降级顺序。
- 测试 HTML 中的 UTF-8、五张卡片、链接和必要字段。
- 测试单个收件人、多个收件人、空格清理、重复地址和无效地址校验。

### 9.2 集成测试

模拟 GitHub、Gemini、GitHub Models、DeepSeek 和 SMTP 响应，覆盖：

- 全部正常
- Gemini 失败后成功降级
- 所有 AI 失败并使用仓库简介
- 单个 README 获取失败
- Trending 三次失败后发送异常日报
- Gmail 发送失败并使工作流失败

### 9.3 邮件快照测试

保存正常日报和异常日报 HTML 快照，验证中文编码、内联样式、五卡布局和错误信息，防止出现乱码或邮件模板回归。

## 10. 验收标准

- 手动触发后，`MAIL_TO` 中配置的所有有效收件人都收到中文正常、包含五张浅色卡片的日报。
- 用户只需更新 `MAIL_TO` Secret 即可在单个和多个收件人之间切换，无需修改代码。
- 每张卡片的中文说明不超过 200 个字符，并包含背景、痛点和优势。
- 同一项目连续两天上榜时，第二天显示“连续霸榜第 2 天”。
- Gemini 不可用时，系统按约定顺序自动降级。
- Trending 无法取得有效前五时，收件人收到包含原因分析和 Actions 链接的异常日报。
- 正常邮件成功发送后，仓库新增当日 JSON 和 Markdown 历史。
- 代码、日志和历史记录中不出现任何密钥。
- 定时工作流每天北京时间 08:00 左右启动，GitHub Actions 排队造成的少量延迟可接受。
